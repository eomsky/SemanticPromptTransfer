# SemanticPromptTransfer v0.21 운영 요구사항

- 기준 버전: `semantic-prompt-transfer==0.21.0`
- 기준일: 2026-08-31
- 기본 표현: L0
- 적용 범위: 승인된 최소 HTML 인터페이스, 문서 생명주기, 다중 문서 RAG, CPU 초안 생성, Word 다운로드

## 1. 목적

v0.21은 v0.20의 검색·근거 우선순위·FEW SHOT 격리 계약을 유지하면서 브라우저 화면과 운영 코드를 연결한다. 사용자는 한 건의 신용조사서와 여러 기타 첨부자료를 업로드하고, 각 파일의 처리률을 확인하며, 파일 삭제와 심사의견 Word 다운로드를 수행한다.

## 2. 고정 인터페이스

메인 화면은 다음 네 기능만 제공한다.

1. 신용조사서 1개 업로드 및 진행률
2. 기타 첨부자료 복수 업로드 및 진행률
3. 업로드 자료현황 조회
4. 심사의견 Word 다운로드 및 진행률

자료현황의 각 행은 파일명, 자료유형, 파일크기, 진행단계, 삭제 버튼을 가진다. 삭제 버튼은 서버가 원본 파일과 해당 문서의 임베딩 벡터 삭제를 모두 확인한 뒤에만 행을 제거한다.

## 3. 범위 키와 단일 벡터 DB

모든 청크와 파일은 다음 복합 범위를 가진다.

`S_d = (tenant_id, case_id, document_id)`

여러 PDF는 하나의 벡터 DB 컬렉션에 적재하되 검색은 최소한 `tenant_id`와 `case_id`로 제한한다. 문서 교체와 삭제는 `document_id`까지 포함한 범위로 수행한다.

전역 청크 ID는 다음 결정적 함수로 생성한다.

`g = H(tenant_id || case_id || document_id || local_chunk_id || level)`

## 4. 파일 처리 상태

| 상태 | 화면 단계 | 기본 진행률 |
|---|---|---:|
| `UPLOADED` | 파일적재 | 15 |
| `VALIDATING` | 파일검증 | 25 |
| `PARSING` | 파일해석 | 45 |
| `INDEXING` | 벡터임베딩 | 70 |
| `READY` | 완료 | 100 |
| `FAILED` | 실패 | 0 |
| `DELETING` | 삭제중 | 기존 값 유지 |
| `DELETED` | 삭제완료 | 100 |

실제 처리기는 더 세밀한 진행률을 전달할 수 있다. 정상 처리 중 진행률은 감소할 수 없다.

## 5. 신용조사서와 첨부자료

신용조사서는 한 심사건에 활성 파일 1개만 허용한다. 규격화된 Excel 매핑으로 셀 단위 기초자료를 읽고 항목별 자료와 공통 자료로 분리한다. 기타 첨부자료는 복수 파일을 허용하고 L0 청크로 변환해 단일 벡터 DB에 적재한다.

근거 우선순위는 고정한다.

`TIER_1 > TIER_2 > TIER_3`

- `TIER_1`: 신용조사서 내 해당 심사항목 기초자료
- `TIER_2`: 신용조사서 공통 기초자료
- `TIER_3`: 기타 첨부자료 검색 근거

FEW SHOT은 여신유형·산업분류·상황 태그로 선택하지만 사실 근거가 아니다.

## 6. 삭제 원자성 경계

서로 다른 저장소를 하나의 DB 트랜잭션으로 묶을 수 없으므로, v0.21은 검증 가능한 단계적 삭제를 사용한다.

1. 레지스트리 상태를 `DELETING`으로 전환해 신규 사용을 차단한다.
2. `tenant_id + case_id + document_id`에 해당하는 모든 벡터를 삭제한다.
3. 같은 필터의 벡터 수가 0인지 확인한다.
4. 파생 산출물과 서버 원본 파일을 삭제한다.
5. 원본 파일이 존재하지 않는지 확인한다.
6. 레지스트리를 `DELETED`로 전환한다.

중간 실패 시 `FAILED`로 남기고 화면에서 성공으로 제거하지 않는다. 감사 이벤트는 보존한다. 사용자의 PC에 있는 업로드 전 원본은 삭제 대상이 아니다.

## 7. HTML 대응 애플리케이션 계약

`OperationalApplicationService`는 다음 작업을 제공한다.

- 업로드 등록
- 파일 처리 상태 갱신
- 신용조사서/기타 첨부자료 그룹 조회
- 문서 범위 삭제
- 심사의견 작업 상태 조회

선택형 FastAPI 어댑터는 업로드, 파일목록, 삭제, 심사의견 시작, 진행조회, Word 다운로드 경로를 제공한다. 실제 PDF/Excel 전처리와 인덱싱은 `UploadProcessor` 어댑터로 주입한다.

## 8. CPU LLM 모듈

초기 생성기는 `TextGenerator` 프로토콜 뒤에 위치한다.

```text
ReviewGenerationOrchestrator
        -> TextGenerator
             -> TransformersCpuGenerator
             -> EvidenceTemplateGenerator (fallback)
```

기본 소형 모델 후보는 `Qwen/Qwen2.5-0.5B-Instruct`이다. 모델은 wheel에 포함하지 않으며 프로세스 시작 시 1회 로드해 CPU에서 재사용한다. 생성은 탐욕적 디코딩, 짧은 출력 한도, 캐시 사용을 기본으로 한다.

기본 생성이 실패하거나 다음 조건을 위반하면 근거형 폴백을 사용한다.

- 현재 심사건 `evidence_id`가 없음
- 현재 근거에 없는 수치가 포함됨
- 빈 출력

폴백은 LLM을 대체하는 최종 품질 구현이 아니라 초기 운영 연결과 실패 복구용이다. 향후 내부 LLM 또는 API LLM은 `generate(messages) -> str` 계약만 구현하면 교체할 수 있다.

## 9. 고정 심사항목과 생성 흐름

1. 재무제표 주요계정
2. 수익성
3. 재무안정성 및 자산의 질
4. 현금흐름 및 채무상환능력
5. 주요 매출처 및 매출비중 변동 추이

진행 흐름은 입력검사, 신용조사서 로드, 첨부자료 검색, 5개 항목 생성·검증, 전체 검증, DOCX 생성, 완료 순서다. 다운로드 버튼은 작업 진행률이 100이고 Word 파일이 존재할 때만 활성화한다.

## 10. 검증 기준

- 기존 L0 청크 회귀 동일성
- 다중 문서 단일 인덱스 UPSERT
- tenant/case 검색 격리
- 파일별 진행률과 화면 단계
- 삭제 후 벡터 수 0
- 삭제 후 서버 원본 부재
- 삭제 실패 시 원본 보존 및 `FAILED`
- CPU 어댑터 교체 가능성
- 근거형 폴백의 수치·인용 검증 통과
- 다섯 심사항목 Word 생성과 진행률 100
- wheel/sdist 설치 및 패키지 내 HTML 포함

## 11. 운영 배포 전 잔여 과제

- 실제 은행 신용조사서 매핑 확정
- PDF 전처리기와 `UploadProcessor` 연결
- 인증·권한·악성파일 검사
- 객체 저장소와 운영 Vector DB 어댑터
- 비동기 작업 큐와 다중 서버 진행률 저장
- 실제 CPU 모델 파일 배포 및 성능 측정
- 내부 LLM 교체와 품질 평가
- 공식 Word 양식과 은행별 교차항목 검증
