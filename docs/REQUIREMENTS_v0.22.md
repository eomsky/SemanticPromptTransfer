# SemanticPromptTransfer v0.22 운영 요구사항

- 기준 버전: `semantic-prompt-transfer==0.22.0`
- 기준일: 2026-08-31
- 기본 표현: L0
- 적용 범위: 제한 시간형 Colab POC, HTML 사용자 화면, 다중 파일 RAG, 심사의견 DOCX

## 1. 목적과 배치 가정

사용자는 외부 URL의 HTML에 접속한다. 애플리케이션 Colab은 테스트 시간에만
기동하며 Google Drive를 사용하지 않는다. 별도 LLM Colab은 선택적으로 연결한다.
실제 운영 배치는 더 복잡해질 수 있으므로 저장소, Vector DB, 인증, LLM은
교체 가능한 경계로 유지한다.

## 2. 회원가입과 로그인

회원가입 필드는 부서명, 이름, 사번으로 한정한다. POC에서 아이디와 초기
비밀번호는 사번이다. 비밀번호 검증값은 PBKDF2-HMAC 해시로 임시 SQLite에
보관한다. 세션 토큰은 만료시간을 가지며 사용자별 해시형 case 범위에 묶는다.
다른 사용자 범위의 문서·작업·다운로드 요청은 거부한다.

이 인증 규칙은 제한된 POC 전용이다. 운영 전에는 SSO, RBAC, 비밀번호 정책,
계정 생명주기, 감사와 개인정보 정책으로 교체해야 한다.

## 3. 최소 HTML

로그인 후 메인 화면은 다음 기능만 제공한다.

1. 신용조사서: 업로드, 양식 다운로드, 업로드 파일명과 단계, `×` 삭제
2. 기타 첨부자료: 복수 업로드, 각 파일명과 단계, `×` 삭제
3. 심사의견: 생성·다운로드 버튼과 진행률

업로드 진행률 막대, 업로드 자료현황 버튼, 자료현황 팝업은 두지 않는다. 파일
진행은 파일명 옆 `파일적재/파일검증/파일해석/벡터임베딩/완료/실패` 텍스트로
표시한다. `×` 성공 응답 후에만 해당 파일명을 화면에서 제거한다.

## 4. 신용조사서 양식

한 심사건에는 활성 신용조사서 XLSX 1개만 허용한다. 인증된 사용자는 고정 API
경로로 양식을 내려받는다. 현재 포함 파일은 다운로드·파싱 연결 검증용 빈 예시다.
실제 양식 제공 시 XLSX와 셀 매핑 JSON을 같은 버전으로 교체한다.

파싱된 모든 사실은 파일명, sheet, cell, 기간, 단위, 수식, 템플릿 버전,
source hash를 보존한다. 신용조사서는 벡터 검색보다 우선하는 정형 기준이다.

## 5. 기타 첨부자료와 단일 논리 Vector DB

허용 형식은 PDF, DOCX, XLSX, TXT, MD이다. 각 파일을 텍스트 블록으로 읽고 L0
청크와 E5 임베딩을 만든다. 여러 파일은 하나의 논리 검색 DB로 사용하되 POC
물리 저장은 문서당 원자적 NPZ shard로 한다.

모든 점은 `(tenant_id, case_id, document_id)`를 가진다. 검색은 tenant와 case를
필수로 하고 교체·삭제는 document까지 포함한다. 한 파일 작업이 다른 파일 shard를
재작성하지 않아야 한다.

## 6. 근거 우선순위와 FEW SHOT

각 심사항목의 근거 우선순위는 고정한다.

1. TIER 1: 신용조사서 내 해당 항목 기초자료
2. TIER 2: 신용조사서 내 공통 기초자료
3. TIER 3: 기타 첨부파일 검색 근거

고정 항목은 주요계정, 수익성, 재무안정성 및 자산의 질, 현금흐름 및
채무상환능력, 주요 매출처 및 매출비중의 5개다. 표시 제목은 결정적 확장
프로필로 검색 쿼리를 풍부하게 한다. FEW SHOT은 항목·여신유형·산업분류·상황
태그로 선택하되 사실 근거에서 격리한다.

## 7. LLM 교체 계약

생성기는 `generate(messages) -> str`의 공급자 중립 계약을 구현한다. 별도 LLM
Colab은 HTTPS OpenAI 호환 endpoint로 연결한다. API key는 환경변수로만 제공하며
소스·HTML에 넣지 않는다. 외부 LLM이 없거나 실패하면 즉시 실행 가능한 근거형
CPU 폴백을 사용한다. 출력은 evidence_id와 수치 근거 검증을 통과해야 한다.

## 8. 삭제와 런타임 종료

파일 `×` 삭제는 대상 벡터 삭제, 동일 범위 count 0, 파생파일 삭제, 서버 원본
부재를 모두 확인한 후 완료한다. 실패 시 성공으로 숨기지 않고 `FAILED`로 남긴다.
사용자 PC에 있는 원본은 삭제하지 않는다.

브라우저 로그아웃은 세션 토큰만 폐기한다. 테스트 시간 종료 시 Colab runtime
root 전체를 삭제해 회원, 업로드, 파생자료, 벡터, 의견 파일을 모두 제거한다.
Google Drive mount와 쓰기는 금지한다.

## 9. API·진행률·다운로드

health, 회원가입, 로그인 외 모든 API는 토큰을 요구한다. 업로드는 백그라운드
처리로 전환하고 파일 목록에서 단계를 조회한다. 심사의견은 별도 job으로 시작해
0~100 진행률을 조회한다. 진행률 100, 출력 경로의 runtime-root 포함, DOCX 실재를
모두 확인한 뒤 다운로드한다.

## 10. 합격 기준

- 소스 컴파일과 전체 단위 테스트 통과
- 실제 CPU E5로 PDF 2개 동시 검색
- 신용조사서 1개에서 정형 사실 추출
- 5개 고정 항목과 DOCX 생성, 진행률 100
- FastAPI 회원가입·로그인·양식·업로드·목록·삭제·생성·다운로드 실요청 통과
- 다른 사용자 case 접근 차단
- 파일 삭제 후 원본·파생파일·해당 벡터 0건
- runtime close 후 root 부재
- v0.21 대비 L0 1,090개 ID·임베딩 입력·전달문 동일
- wheel/sdist 격리 설치와 패키지 내 HTML/XLSX 포함

## 11. 운영 전 잔여 과제

- 실제 은행 신용조사서 XLSX와 셀 매핑 확정
- 공식 심사의견 Word 양식
- OCR·복잡표·스캔 PDF 전처리
- 기업 SSO/RBAC, 개인정보·감사·보존 정책
- 악성파일 검사, 암호화 저장소, 관리형 Vector DB
- 분산 작업 큐와 다중 서버 상태 저장
- 터널 및 CORS 허용 URL 통제, TLS, rate limit
- 내부 LLM 품질·지연·메모리·보안 평가
